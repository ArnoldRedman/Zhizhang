# 写作质量门与三档审查设计

> 2026-09-20 起草，2026-09-21 按已落地的代码修订。目标：让"懒人连续创作"写出的章节过得了番茄"AI 粗制滥造 / 格式混乱 / 结构失常 / 空洞水文"四条细则，并把 oh-story-claudecode 里可复用的机制搬进应用。本文只保留仍然成立的约束与取舍；代码位置见 ARCHITECTURE.md。

## 一、来源与取舍

参考了两份材料：linux.sb 帖子《今天分享 ai 写小说的流程》（oh-story-claudecode + opencode + GLM，83 章过签上推荐，14.87 亿 tokens）和番茄平台新规截图（四条违规细则）。oh-story 仓库 `skills/` 已通读，摘出以下机制：

| oh-story 机制 | 本应用落法 | 不照搬的原因 |
|---|---|---|
| `check-ai-patterns.js`（7 条 blocking + 15 条 advisory） | 移植为 `packages/contracts/src/prose-lint.ts` 纯函数，两端共用 | 原脚本是 CLI，读文件；这里要在内存里对草稿跑 |
| `check-degeneration.js`（复读 / 截断 / 拒绝语 / 工程词） | 并入 `prose-lint.ts` | 同上 |
| `normalize-punctuation.js`（省略号、破折号、分隔线；引号按模式转） | `packages/contracts/src/punctuation.ts`；全书统一引号做成一次性操作 | 原脚本默认 keep 引号，本书恰恰是引号漂了 8 次 |
| `check-outline-copy.js`（正文照搬细纲 ≥16 字） | 并入 `prose-lint.ts` 的 `outlineCopy` 项 | — |
| 细纲固定字段 + `check-outline-contract.js` | 构思提示词要求写清"本章变化"与四到八个情节点，不做机械校验 | 原细纲 30 多个字段，是给 Opus 用的；DeepSeek 写不满会硬填；缺了让审查的架构视角去判，比拿正则卡构思稳 |
| 追踪状态卡 7 栏（当前位置 / 长期约束 / 核心角色状态 / 活跃伏笔 / 近三章速记 / 下一章承诺 / 连贯性风险） | 已有的故事账本加"上一章留给本章的事（下一章承诺）"与"作者真相"两段；"连贯性风险"由一致性视角的 nextChapterRisks 进报告与待答文档，不回写账本 | 账本由记忆数组实时渲染，没有第二份状态可回写 |
| 作者真相 vs 读者已知 | 记忆提炼新增 `readerKnown` / `authorTruth` 两个字段 | — |
| 三档审查 full / lean / solo，四视角 | 单模型串行四次调用，四个视角各一份提示词；lean 只跑架构 + 一致性；solo 只跑本地 lint + 一次通用审查 | 没有多 agent，但四次独立调用比一次"全看"稳 |
| 番茄 rubric（六项 PASS/FAIL） | 进审查提示词的"审查基准包" | — |
| 新增物三档（现场材料 / 申报收编 / blocking） | 记忆提炼多一个 `newlyIntroduced` 字段，列进"给作者｜待答"由作者定要不要建卡 | 不在正文末尾加申报块：正文提示词保持只说写什么 |
| 拆文 Stage 0-6 + `文风.md` + 情绪模块 + 节奏 | 拆书增加"全书聚合"一步：产出文风档案（含原文锚点）、情绪模块、节奏表；写作时按目标情绪挑一条模块、一段锚点 | 只做主对标一本，不做跨书召回 |
| 字数：欠不补、超不压 | 连续创作和旧章批量重写仅在目标字数～1.2 倍内自动采用；不合格稿留草稿，不覆盖旧章 | 已实现 |
| 反抄壳：模块只留情绪链与功能位，人物场景道具触发条件全换 | 写进拆书聚合提示词与召回段落 | 帖子 15 楼承认套壳，原设计有防线但作者"完全不干预"绕过了 |

## 二、写一章的完整链路（改造后）

```
资料组装 ──► 构思（简短确定本章事件、人物动机和结尾；绑定对标时看情绪模块与节奏表）
   │              │
   ▼              ▼
写正文（纯文本，温度 0.85，带最近五章开头结尾句 + 上一章承诺；绑定对标时只带一段同基调锚点与一张模块）
   │
   ▼
本地验证门（不调模型，毫秒级）
   ├ prose-lint：风格句式降为 advisory；截断 / 复读 / 占位符 / 工程词泄漏才定向修订一次 → 复扫
   ├ outlineCopy：≥16 字照搬构思 → 进报告（advisory）
   ├ 与最近五章的开头句 / 结尾句同型 → 进报告（advisory，连续三章同型升 blocking）
   ├ 对话密度 / 沉默词密度 / 时间开头段 → 进报告
   └ 引号风格与全书不一致 → 直接归一（确定性替换，不进报告）
   │
   ▼
审查（按项目设置 full / lean / solo；默认 lean）
   ├ 架构视角：推进、变化、钩子、番茄 rubric
   ├ 人物视角（full）：声线、动机、关系尺度
   ├ 文字视角（full）：AI 味分级、解释腔、结尾升华
   └ 一致性视角：事实、时间线、伏笔、读者已知 vs 作者真相
   │
   ▼
裁决：advances=false 或 repeatedEvents 非空 → 换事重写一次；带原文证据的 S1 事实矛盾 → 定点修订一次；其余只出报告
   │
   ▼
记忆提炼（新增 readerKnown / authorTruth / nextChapterPromise / newlyIntroduced）
   │
   ▼
账本重渲染（含上一章承诺、作者真相）→ 下一章
```

模型调用次数：构思 1 + 正文 1 + 审查 1～4 + 记忆 1，加上最多三次修订（验证门定向修订、换事重写、事实矛盾定点修订各至多一次）。lean 档一章约 5 次，full 档约 7 次。重写稿与修订稿只再过验证门，不再进审查，避免审改循环。

## 三、本地验证门的规则

全部在 `packages/contracts/src/prose-lint.ts`，输入正文字符串，输出 `Finding[]`。每条：`type`、`severity`（blocking / advisory）、`line`、`excerpt`、`message`。字节稳定，可单测。

### 风格句式在写作链里降为 advisory；只有结构性坏稿会触发修订

| type | 现象 | 判定 |
|---|---|---|
| not-is-comparison | 「不是 A，(而)是 B」 | 引号外；排除「是不是」「不是吗」「就是 / 也是」连词 |
| reverse-not-is | 「是 A，不是 B」 | 同上排除表 |
| negation-parade | 「没有 X，没有 Y，」连排 / 「没 X，没 Y，只是 Z」 | 引号外 |
| voice-contrast | 「声音不大 / 不高…却 / 但…」 | 引号外 |
| em-dash | `——` `—` `--` | 全文 |
| trailer-ending | 文末 600 字内「没人知道 / 才刚刚开始 / 正朝着…压过去 / 即将来临」 | 文末窗口 |
| trailer-summary | 文末 600 字内「这一夜注定 / 这一切都结束了 / 新的篇章 / 命运的齿轮」 | 文末窗口 |
| verbatim-repeat | 长句（≥12 可见字）出现 ≥3 次，或相邻整行重复（≥8 字） | 引号外 |
| truncated | 末行不以句末标点收尾 | 全文 |
| placeholder-leak | 「作为 AI」「此处省略」「未完待续」「我无法继续」 | 全文 |
| meta-leak（一级） | 章纲 / 情节点 / 细纲 / 目标情绪 / 章尾钩子 | 标题行以外 |

### advisory（进报告，不自动改）

period-stutter（连续 6 个 ≤5 字叙述句）、long-paragraph（>200 字）、micro-action-tic（「了下 / 了一下」≥5 次且 ≥6/千字）、stock-reaction-tic（指尖 / 指节 / 喉结 / 眼圈 / 声音放轻 ≥4 处且 ≥1.5/千字）、action-list-tic（同段 ≥5 个动作动词且 ≥4 个逗号）、abstract-summary-tic、cliche-density-tic（≥8 处且 ≥12/千字）、metaphor-density-tic（≥7 处且 ≥3/千字）、reasoning-chain-tic、quote-emphasis-tic（叙述里 1～4 字加引号 ≥3 处）、formulaic-parallelism、meta-leak（二级：本章 / 上一章 / 伏笔 / 读者）、outline-copy（与构思连续重合 ≥16 汉字）。

### 本应用自加的三条（针对这本书实测出的病）

| type | 现象 | 判定 |
|---|---|---|
| opening-echo | 开头句与最近五章之一同型 | 报时式（周几 + 时间 + 地点）/ 灯亮了一夜式 / 钥匙式；连续三章同型升 blocking |
| ending-echo | 结尾句与最近五章之一同型 | 落在灯上 / 「没动、没关、没再说」否定式静止 / 抒情升华；连续三章升 blocking |
| silence-density | 「没问 / 没说话 / 没再说 / 默默 / 淡淡 / 嗯了一声 / 点了点头」≥2.5/千字 | 引号外 |

对话密度低于 3/千字单独报 `dialogue-sparse`，advisory。

### 引号归一

`punctuation.ts`：`normalizeQuotes(text, style)`，style 取自项目设置，没设就按已有正文侦测多数风格，全无引号时缺省中文弯引号「“”」。规则：`「」` 与 ASCII `"` 转成目标风格，`『』` `‘’` 是对话里的嵌套引用不动，`【】` 不动（系统面板 / 标注），未闭合的引号所在行原样保留并计数。同时把 `…+` `\.{3,}` `——` `—` `--+` 按 oh-story 的 `choosePauseReplacement` 规则换成句号 / 逗号 / 冒号 / 删除，`---` 分隔线删除。这一步在"采用草稿"和"全书统一标点"两个入口跑。

## 四、审查三档

`chapter.review` 增加 `mode: 'full' | 'lean' | 'solo'`，项目设置里选，缺省 lean。运行时把它拆成串行调用：

| 视角 | full | lean | solo | 检查项 |
|---|---|---|---|---|
| 本地 lint | ✓ | ✓ | ✓ | 上节全部 |
| 架构 | ✓ | ✓ | 合并进一次通用审查 | 本章改变了什么；读者为什么翻下一页；结尾落在动作画面还是总结；番茄六项 PASS/FAIL；是否重复账本已发生事件 |
| 人物 | ✓ | | | 每个出场人物是否按卡说话；一整章只在沉默点头的人；对话三症状（问答式 / 科普嘴 / 不分场合） |
| 文字 | ✓ | | | AI 味分级；解释腔 / 上帝视角 / 安排感；升华收尾；lint 没覆盖的模板句 |
| 一致性 | ✓ | ✓ | | 事实 / 时间线 / 物品 / 称谓；读者已知 vs 作者真相有没有泄底；上一章承诺是否兑现 |

统一 Findings：`{ severity: S1|S2|S3|S4, category, location, evidence, issue, fix }`。综合 Verdict：无 S1/S2 → APPROVE；有 S2 → CONCERNS；有 S1 → REJECT。

裁决规则（写作图里）：
- 架构判 advances=false 或 repeatedEvents 非空 → 换事重写一次（已有）。
- 一致性给出 S1 且带 evidence → 定向修订一次，提示词只含这几条，其余保持原样。
- 其他一律进报告和「给作者｜待答」。

审查提示词不再叠"不得 / 必须"，改为每个视角三到五个问题加番茄 rubric 表，输出 JSON。

## 五、账本 7 栏与记忆字段

记忆提炼（memory.write）新增：

| 字段 | 内容 | 用途 |
|---|---|---|
| readerKnown | 本章读者新知道的事（一条一句） | 一致性视角查泄底 |
| authorTruth | 本章埋下但读者还不知道的真相（可空） | 同上；进账本"作者真相"栏，不进正文提示词的"读者已知" |
| nextChapterPromise | 本章结尾对下一章的承诺（一到两句） | 账本"下一章承诺"栏；下一章构思必须回应 |
| newlyIntroduced | 本章新出现的具名人物 / 地点 / 物件 / 规则 | 收编进卡片候选（给作者｜待答里列出） |

账本在原有结构（当前位置、已发生事件一章一行、更早章节只列标题、长线伏笔）上加两段：最后一章的"下一章承诺"，最近六章的"作者真相"（标明角色不能提前说破）。一致性视角的 nextChapterRisks 进审查报告与"给作者｜待答"，不进账本。

## 六、拆书对标

拆书管理现有产出是逐章的（摘要、细纲、节拍、人物、伏笔、节奏）。加一步"全书聚合"（一次调用，输入全部章节摘要）：

- `文风档案`：句长分布（本地算）、标点习惯、段落节奏、对话标签习惯、角色语气区分，加 3～5 段原文锚点（各 300～500 字，按基调标注；只认首中尾三章样本里逐字存在的段落，模型复述的丢掉）。存为 WritingStyle，锚点放 `content` 末尾的"原文锚点"节。
- `情绪模块`：3～6 张模块卡（读者需求 / 触发器 / 戏剧单元 / 可替换要素 / 反抄袭提醒）。
- `节奏表`：关键信息推进（信息 → 扩写技法 → 触动点 → 爆发 / 冷却）。

写作时的召回（运行时 `application/benchmark.ts`）：项目绑定了来源拆书（`sourceDismantleBookId`）且做过全书聚合时，构思阶段看全部情绪模块与节奏表；正文阶段按构思里出现的基调词挑一张模块、一段锚点，对不上就一段都不带；提示里写明"学它的手法和情绪推进，不抄字句；人物、场景、道具、触发条件全换"。

## 七、连续创作的接入点

验证门、审查、裁决全在运行时的写作图里（`chapter.write` 一次调用走完），桌面端只负责喂资料和收结果：

1. 桌面端组装资料时带上审查档位、引号风格、允许句式、最近五章开头结尾句、上一章承诺、对标聚合。
2. 图里：正文 → 验证门（标点归一、lint；只有截断/复读/占位符/工程词泄漏自动修一次）→ 审查 → 裁决（换事重写 / 事实矛盾定点修订）→ 修订稿再过验证门 → 结束。
3. 桌面端采用草稿、提炼记忆（新字段进账本）；验证门未改净的 blocking、S1/S2 问题、下一章风险、本章新增物进"给作者｜待答"。

单章手动运行走同一条链，草稿面板多一块折叠的"验证门"清单。

## 八、旧章重写

做在应用里（写作操作台的"重写旧章"），不做应用外脚本：脚本要绕过 Tauri 落盘、自己维护快照与记忆，等于把写作链再抄一遍。

- 输入：章号区间、方式（保事件换写法 / 从构思重来）。与连续创作互斥，逐章串行，停止在本章写完后生效。
- 保事件：本章记忆里的大意、时间线、人物变化、关系、章末落点当作"作者的要求"喂给构思，跳过节拍表与章纲生成；从构思重来：原稿作废，走和写新章一样的懒人流程（缺节拍表、章纲就先生成）。
- 每章走完整链路；重写稿只有达到目标字数且不超过 1.2 倍才自动采用，其他情况留草稿，原章不动。合格重写稿进入章节历史并提炼记忆。
- 重写历史章时资料只到本章之前：聚合文档按本章之前的记忆临时重建，审查按"历史章节"口径（去掉账本里的最新进度行，不拿后续章节的事实要求本章）。
- 先挑一章验证原始草稿的文风、对话和字数；未确认效果前，不批量重写历史章。

## 九、正文批注与常驻卡片（2026-09-21，参考 Denova 后补的两项）

- **正文批注定点修订**：编辑器工具栏"批注"，选中一段写一句要求，存在章节的 `annotations` 里（按原文片段定位，不存偏移）。"按批注修订"把每条批注定位到所在段落，同一段的合并，逐段调 `text.transform` 的 `annotate` 模式：模型只看到那一段、前后各四百字和段落里出场的人物卡，只输出改后的那一段，其余正文不经过模型。改完写回并删掉已处理的批注，旧稿进章节历史；原文片段已不在正文里的批注标为失效。
- **常驻卡片**：卡片的 `pinned` 开关（侧栏卡片列表"设常驻"）。常驻卡在构思阶段与生成章纲时每章必带（模型知道主角现在的状态），排在最前、不占自动挑选的名额。但常驻不等于必须出场：正文阶段只带构思里点到名的卡（`castCards`），支线章、第二视角的伏笔章构思没安排主角，正文提示词里就没有主角卡；金手指卡是世界规则，一律带。

## 十、技能路由、卡片刷新与 AI 率门（2026-09-21）

- **技能自动路由**（`routeChapterSkills`）：项目设置"作品默认技能"（文风标签页里勾，只列写作与润色类）每章必带，奠定全书写法；作者本次勾选的其次；再按章纲、节拍、指令里原样出现的技能标签或显示名追加，上限四条。流程词（正文、章节、续写、长篇、大纲……）不算场景标签，审查、拆书、工具类技能永不进正文。日常过渡章命不中任何标签就只带默认技能。
- **从构思重来时丢掉旧章纲**：重写旧章选"从构思重来"会先删掉绑定到本章的旧章纲（阶段节拍表不动，它是按总纲规划的一段），再走懒人流程重新生成章纲；否则新构思会被旧章纲拉回原稿那件事。
- **卡片每十章刷新**（`card.refresh`）：连续创作每写满十章，一次模型调用把全部卡片对着最近十章正文重写"当前状态"，只改状态不动卡片正文，没变化的卡返回空串不动。卡片面板也有手动按钮。逐章记忆提炼只更新本章点到名的卡，没出场的卡状态会停在旧处，这是补它的。
- **AI 率只读指标**：本地启发式估计句长、连接词等特征，写作后展示分数，不再凭这个数字自动改段落；检测口径与平台不一致，作者可按正文实际质量判断。

## 十、不做的事
